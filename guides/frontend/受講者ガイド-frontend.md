# ミニEC フロントエンド改修トレーニング — 受講者ガイド

バックエンド編と同じく、**すでに動いている画面（`training-frontend`）の不具合を直す**練習です。<br>
今回いじるのはブラウザで動く JavaScript。素の HTML + JavaScript だけで作られているので、**DOM（画面の部品）を直接触るコード**をたくさん読むことになります。

この研修で身につけること:

- JavaScript の基礎（比較・型・スコープ・クロージャ・非同期処理）
- DOM 操作（要素の取得・作成・追加、属性と class と style、イベント）
- ブラウザの **DevTools** で原因を追う力（「なんとなく書き換える」から卒業する）
- 画面とサーバーの**どちらが悪いか**を切り分ける力

---

## 1. 準備

環境構築（リポジトリのクローン・backend の起動・フロントの起動）は [バックエンド編の受講者ガイド §1](../backend/受講者ガイド-backend.md#1-最初にやること環境構築) と同じです。<br>
金額計算のルールも [§2](../backend/受講者ガイド-backend.md#2-金額の計算ルール重要) を参照してください。

- backend は **`main` のまま**起動します（フロント課題ではバックエンドのブランチは切り替えません）。
- 注文やキャンセルを繰り返すとデータが変わります。最初の状態に戻したいときは、backend を止めて `training.db`（と `-shm` / `-wal`）を削除してから起動し直してください（初期データが入り直します。手順は backend の README 参照）。

## 2. DevTools の使い方（必修）

ブラウザで `F12`（Mac は `Cmd + Option + I`）を押すと DevTools が開きます。フロントにはテストコードがないので、**DevTools が一番の相棒**です。

| パネル | 何に使う | こんなときに |
|---|---|---|
| **Console** | エラーの確認・JS をその場で試す | 赤いエラーが出ていないか最初に見る。`typeof x`、`[1,2] + ""` などを試す |
| **Elements** | 今の画面の HTML（DOM）と CSS を見る | 「見えない」「色が違う」「ボタンが押せない」。要素の `id` / `class` / 属性 / 効いているスタイルを確認 |
| **Elements → Event Listeners** | 要素に付いているイベント処理を見る | 「押しても反応しない」「押すと変なことが起きる」 |
| **Sources** | ブレークポイントで止めて変数を見る | 「この時点で変数に何が入っている？」を確かめる。行番号をクリックで設定 |
| **Network** | サーバーとの通信を見る | 「送った値は？」「サーバーは何を返した？（ステータス・本文）」。スロットリングで通信を遅くもできる |

> **コツ**: 「たぶんここが悪い」と思ったら、**直す前に**ブレークポイントや Console で「本当にそうなっているか」を確かめる。<br>
確かめた事実は PR の説明にそのまま書けます。

## 3. テストの代わりに — 動作確認チェックリスト

フロントには自動テストがありません。その代わり、直した後に**次の項目のうち影響範囲のものを手で確認**します（自分の修正で別の機能を壊していないか＝デグレの確認）。

- [ ] 店舗: 商品一覧が1回ずつ表示される（「読み込み中...」が残らない）
- [ ] 店舗: 在庫切れのステッカーは「在庫切れ」で押せない。他の商品は押した商品がカートに入る
- [ ] 店舗: カートの「削除」で行が消え、小計が変わる
- [ ] 店舗: カートに入れると「税抜小計（目安）」とクーポン欄・注文ボタンが出る
- [ ] 店舗: クーポンなしで注文 → 注文番号と税込金額が表示され、在庫が減る
- [ ] 店舗: `SALE10` で注文 → 割引後の金額になる
- [ ] 店舗: `SALE99`（存在しない）で注文 → エラーメッセージが出て、注文は作られない
- [ ] 注文履歴: 明細表が正しく表示され、余計な文字が出ていない
- [ ] 注文履歴: キャンセルすると、その注文が「キャンセル済み」になりボタンが消える
- [ ] 管理: 価格を変更すると、その価格に更新される
- [ ] 全ページ: ヘッダーで今いるページのタブが青くなる
- [ ] 全ページ: Console に赤いエラーが出ていない

※ 影響範囲を見て必要な項目をチェックしてください。

## 4. 課題の進め方

流れはバックエンド編の [§4](../backend/受講者ガイド-backend.md#4-課題の進め方毎回この順番で) と同じです。違うのは次の点だけ。

- チェックアウトするのは **`training-frontend` の `challenge/f...` ブランチ**（backend は `main` のまま）。
- 「全テスト緑を確認」の代わりに、**課題ファイルの再現手順で症状が消えること**と **§3 のチェックリストのうち影響範囲の項目が OK** であることを確認する。
- PR の「どう確認したか」には、**DevTools で何を見て原因を特定したか**も書く（例: 「Elements でボタンに `disabled="false"` が付いているのを確認」）。

ブラウザのキャッシュで古い JS が動くことがあります。直したのに変わらないときは `Ctrl + Shift + R`（強制再読み込み）を試してください。

## 6. 困ったときのチェックリスト

- 症状を1文で言えるか？（「○○すると△△になる、本当は□□のはず」）
- Console に赤いエラーは出ている？ 出ているなら、どのファイルの何行目？
- 問題は「通信」「データ」「画面」のどれ？ Network で見た通信は正しい？
- 直す前に、ブレークポイントや Elements で**事実を確かめた**か？
- 直した後、§3 のチェックリストの影響範囲の項目は OK か？
- 変更は最小限か？ 関係ない箇所まで書き換えていないか？

行き詰まったら、抱え込まず講師に相談してください。
