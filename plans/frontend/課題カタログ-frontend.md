# ミニEC フロントエンド研修課題 カタログ（講師・教材管理者用）

> このカタログは **`training-frontend`（素の HTML + ES Modules + fetch）専用**の課題を定義する。バックエンド課題（A1〜A8 / B / C / D）は `plans/common/課題カタログ.md` を参照。
> 実際の仕込み diff・ヒント・解答は `plans/frontend/課題-仕込みdiff-frontend.md` に置く。
> **取り扱い注意**: 各課題の「壊している不変条件」は解答そのもの。受講者には渡さない。受講者には `guides/frontend/受講者ガイド-frontend.md` と課題ブランチだけを渡す。

## 0. このドキュメントの位置づけ

フロントはどの言語版バックエンドとも共有されるため、**本カタログの課題は全言語版で同一**に成立する（バックエンドは `main` のまま起動すればよい）。

```
training-shared/plans/frontend/課題カタログ-frontend.md     ← 本書（狙い・症状・不変条件・難度）
training-shared/plans/frontend/課題-仕込みdiff-frontend.md  ← 実 diff・ヒント・解答
training-shared/guides/frontend/受講者ガイド-frontend.md    ← 受講者向けの進め方
training-shared/guides/frontend/challenges/F1.md …          ← 受講者向け各課題（解答なし）
```

### 狙い

- JavaScript の基礎（比較・型・スコープ・クロージャ）と **DOM 操作**、**非同期処理と HTTP**、**XSS** を、動いているアプリの不具合修正を通して一通り学ぶ
- ブラウザの **DevTools**（Console / Elements / Network / Sources のブレークポイント / Event Listeners）で原因を追う力をつける

### 課題の2タイプ

| タイプ | やること | 担保のしかた |
|---|---|---|
| **F バグ修正型** | `main` を1箇所だけ壊したブランチを渡し、症状から原因を特定して直させる | フロントにテストは無い。**課題ファイルの再現手順で症状が消える＋受講者ガイドの動作確認チェックリストのうち影響範囲の項目が OK** |
| **FC 機能追加型** | 既存の作法（関心の分離）に合わせて、DOM を自分で組み立てる機能を足させる | 要件の確認観点を満たす＋動作確認チェックリストのうち影響範囲の項目が OK＋レビューで層の分離を確認 |

### ブランチ運用

バックエンドと同じ。`training-frontend` に `challenge/f<番号>-<症状名>` を `main` から1つずつ作り、各1コミット（メッセージは `課題F<番号> セットアップ`）で仕込む。受講者は課題ブランチから自分のブランチを切り、PR のマージ先は対象の `challenge/...`。

> ブランチ名・コミットメッセージには**症状だけ**を書き、原因（`await` / `innerHTML` など）は書かない。

## F. バグ修正型

各課題は **狙い / 受講者に見える症状 / 壊している不変条件（＝解答の核）/ 難度** で定義する。

### トラック1: 言語の基礎

#### F1. キャンセル済みの注文が「確定」に見える ★☆☆
- **狙い**: `=`（代入）と `===`（比較）の取り違え。代入式も値を返す（`if (x = "A")` は常に真）こと。
- **症状**: 注文履歴で、キャンセルした注文のバッジが「確定」のまま（キャンセルボタンは消えるので、状態自体は正しく取れている）。
- **壊している不変条件**: ステータスの判定は比較（`===`）で行う。

#### F2. 注文明細の表の上に謎の「,」が出る ★☆☆
- **狙い**: 配列をテンプレートリテラルに埋め込むと `toString()` で `,` 区切りの文字列になる。`map` → `join("")` の定石。
- **症状**: 明細が2行以上ある注文だけ、明細表の上に「,」が表示される（1行の注文は正常）。
- **壊している不変条件**: HTML 文字列の配列は `join("")` で連結してから埋め込む。

#### F3. 管理画面で正しい価格を入れてもエラーになる ★☆☆
- **狙い**: `input.value` は常に**文字列**。`Number.isFinite` は文字列に対して常に `false`。
- **症状**: 価格に `500` など正しい数値を入れて「価格を更新」を押しても、必ず「価格は 0 以上の数値で入力してください。」になる。
- **壊している不変条件**: フォームの値は数値に変換してから検証・送信する。

#### F4. どの「カートに追加」を押しても同じ商品が入る ★★☆
- **狙い**: `var` は関数スコープ。ループ内のクロージャは変数を「その時の値」ではなく「変数そのもの」で掴む。
- **症状**: どの商品の「カートに追加」を押しても、一覧の最後の商品（キーホルダー）がカートに入る。
- **壊している不変条件**: ループ内でハンドラに渡す値は、各周回ごとに別の束縛（`const` / `let`）にする。

### トラック2: DOM

#### F5. 商品を追加してもカートの小計・注文欄が出ない ★☆☆
- **狙い**: `getElementById` は見つからないと `null` を返す。HTML の `id` と JS の対応を Elements パネルで確かめる。
- **症状**: 「カートに追加」で商品の行は出るが、「税抜小計（目安）」もクーポン欄・注文ボタンも出ない。Console に `Cannot set properties of null`。
- **壊している不変条件**: JS が取得する要素の `id` は HTML に実在する。

#### F6. ヘッダーで今いるページのタブがハイライトされない ★☆☆
- **狙い**: JS が付ける class 名と CSS セレクタの対応。Elements パネルで付いている class と効いているスタイルを見る。
- **症状**: どのページでも現在ページのタブが青くハイライトされず、そのタブだけ他のタブと見た目（余白など）も崩れる。
- **壊している不変条件**: アクティブなタブには `nav-link` と `active` の2つの class が付く（CSS は `.nav-link.active`）。

#### F7. カートに入れてもクーポン欄・注文ボタンが出てこない ★☆☆
- **狙い**: `style.display` による表示切替。初期 HTML の `style="display:none;"` を JS で戻す流れを追う。
- **症状**: カートに商品は入り小計も出るが、クーポン欄と「この内容で注文する」ボタンがいつまでも出ない。エラーも出ない。
- **壊している不変条件**: カートが空でないときは注文欄を表示状態にする。

#### F8. 在庫があるのに全商品のボタンが押せない ★★☆
- **狙い**: **属性とプロパティの違い**。`disabled` は「属性が存在するだけで有効」で、`setAttribute("disabled", false)` は `"false"` という文字列の属性を付ける。
- **症状**: 全商品のボタンが「カートに追加」と表示されているのに、グレーで押せない。
- **壊している不変条件**: 真偽値で状態を切り替えるときは `button.disabled = 真偽値`（プロパティ）を使う。

#### F9. 注文するたびに商品一覧が増殖する ★★☆
- **狙い**: 「データを受け取って描き直す」再描画パターンでは、描く前にコンテナを空にする。
- **症状**: 起動直後から「読み込み中...」が消えずに残る。注文を確定するたびに商品一覧が二重・三重に増える。
- **壊している不変条件**: 再描画の前にコンテナの中身をクリアする。

#### F10. 「カートに追加」ボタンが最後の商品にしか無い ★★☆
- **狙い**: **1つの DOM ノードは1箇所にしか置けない**（`appendChild` は移動）。`addEventListener` は重ねて登録される。
- **症状**: ボタンが一覧の最後の商品（キーホルダー）にだけ表示され、他の商品には無い。押すとほぼ全商品がカートに入り、ステッカーの在庫アラートも出る。
- **壊している不変条件**: 商品ごとにボタン要素を新しく作る。

#### F11. 管理画面で価格を変えても元の価格のまま「更新しました」 ★★☆
- **狙い**: DOM の値を**いつ**読むか。描画時に読んだ値をクロージャが掴むと、その後の入力は反映されない。
- **症状**: 価格欄を書き換えて「価格を更新」を押すと「更新しました」と出るが、価格は元のまま。
- **壊している不変条件**: 入力値はボタンが押された時点で読む。

#### F12. カートの「削除」ボタンが全部効かない ★★★
- **狙い**: **`innerHTML +=` は中身を文字列化して作り直すため、既存要素に付けたイベントリスナーが消える**。「機能追加（件数表示）でデグレ」の実務感。
- **症状**: カートの下に「◯ 種類」と件数が出るようになった代わりに、「削除」ボタンを押しても何も起きない。エラーも出ない。
- **壊している不変条件**: リスナー付き要素があるコンテナに追記するときは `appendChild` / `insertAdjacentHTML` を使い、`innerHTML` を作り直さない。

#### F13. 注文のキャンセルで別の注文がキャンセルされる ★★★
- **狙い**: 検索の起点（`document.querySelector` と `要素.querySelector`）。まだ DOM に挿入していない要素は `document` から見つからない。リスナーの多重登録を Event Listeners パネルで確認する。
- **症状**: 注文履歴の一番上の注文で「注文をキャンセル」を押すと、**2件目以降の注文番号**の確認ダイアログが次々に出て、それらがキャンセルされる。2件目以降のボタンは押しても何も起きない。
- **壊している不変条件**: 各カードのボタンは、そのカードの中から探してリスナーを付ける。

### トラック3: 非同期と HTTP

#### F14. 注文完了メッセージが「undefined」「¥NaN」になる ★★☆
- **狙い**: `async` 関数は Promise を返す。`await` しないと結果は Promise のままで、失敗も `try/catch` で捕まらない（`Uncaught (in promise)`）。
- **症状**: 注文すると「注文番号: undefined / ステータス: undefined / ¥NaN」（注文自体は作られている）。無効なクーポンで失敗するはずの注文でも同じ「完了」表示が出てカートが空になり、Console に `Uncaught (in promise)`。
- **壊している不変条件**: API 呼び出しの結果は `await` して受け取る。

#### F15. 無効なクーポンでも「注文が完了しました」 ★★☆
- **狙い**: `fetch` は 4xx/5xx でも例外にならない。`res.ok` / ステータスコードで判定する。Network パネルでレスポンスを読む。
- **症状**: 存在しないクーポン `SALE99` で注文すると「注文が完了しました！注文番号: undefined / ステータス: 400 / ¥NaN」。注文は作られていない（注文履歴に無い）。
- **壊している不変条件**: HTTP エラー時はサーバーのエラーメッセージで例外を投げ、画面にエラーとして出す。
- **補足**: バックエンド課題 A5（サーバー側の検証）と対。「サーバーは正しく 400 を返しているのに、フロントが成功扱いしている」切り分け。

#### F16. 注文ボタンの連打で同じ注文が2件できる ★★☆
- **狙い**: 非同期処理中の UI 状態管理・二重送信防止。Network パネルのスロットリングで再現しやすくする。
- **症状**: 「この内容で注文する」を素早く2回押すと、同じ内容の注文が2件作られ在庫も2回分減る。
- **壊している不変条件**: 通信中は注文ボタンを無効化し、完了後に戻す。

### トラック4: セキュリティ

#### F17. クーポン欄に入れた文字でアラートが出る（XSS）★★★
- **狙い**: `innerHTML` と `textContent` の違い。サーバーのエラーメッセージも利用者の入力を含みうる＝信用しない。
- **症状**: クーポン欄に `<img src=x onerror=alert(1)>` と入れて注文すると、アラートが出る（スクリプトが実行される）。
- **壊している不変条件**: 文字列は `textContent` で入れる。`innerHTML` を使うなら必ず `escapeHtml()` を通す（CLAUDE.md の約束ごと）。

## FC. 機能追加型（DOM を自分で組み立てる）

> 正解は一通りではない。要件と確認観点を示し、**既存の関心の分離**（fetch は `core/api.js`、状態は `core/cart.js`、DOM は `ui/render.js`、結線は `entries/*.js`）を守っているかをレビューで見る。ブランチは不要（`main` から着手）。

#### FC1. 商品の絞り込み検索 ★☆☆
- **要件**: 商品一覧の上に検索ボックス。入力のたびに商品名の部分一致で一覧を絞り込む。**サーバーへ再問い合わせしない**（取得済みの一覧を使う）。空なら全件。
- **学び**: `input` イベント・`Array.prototype.filter`・再描画。
- **確認観点**: 「ノ」で ノート のみ / 該当なしで「商品がありません。」/ 空で全件 / 絞り込み中でも「カートに追加」が正しい商品で動く。
- **補足**: サーバー側に検索 API を作る方法と比べて、「どちらで絞るべきか」を議論させてもよい。

#### FC2. カートの数量 ± ボタン ★★☆
- **要件**: カートの各行に「−」「＋」。＋は在庫上限で無効、−で 0 になったら行を削除。小計も追従。
- **学び**: `core/cart.js` に DOM を知らない純粋関数（例 `changeQuantity`）を足す → `entries` で結線 → `ui/render.js` で描画、の分担。
- **確認観点**: Tシャツ（在庫10）は 10 で＋が無効 / −で 0 → 行が消える / 数量変更後の注文で数量が正しく送られる。

#### FC3. 注文明細の開閉 ★★☆
- **要件**: 注文履歴の明細表を初期は閉じ、「▶ 明細を見る」ボタンで開閉。開いているときは「▼ 明細を閉じる」。
- **学び**: `hidden` 属性 / `classList.toggle`・`aria-expanded` によるアクセシビリティ。
- **確認観点**: 注文ごとに独立して開閉する / キャンセル後の再描画で壊れない。

#### FC4. 管理画面の Enter / Esc 操作 ★★☆
- **要件**: 価格欄で Enter → 「価格を更新」と同じ処理、Esc → 入力を現在価格に戻す。
- **学び**: `keydown`・`event.key`・既存の `savePrice` の再利用（ロジックを複製しない）。
- **確認観点**: Enter で更新・メッセージ表示 / Esc で元の値 / IME 変換確定の Enter で誤送信しない（`event.isComposing`）。

#### FC5. トースト通知部品 ★★★
- **要件**: `alert()` を置き換える通知部品を `js/ui/components/toast.js` に作り、全ページの `alert` を置き換える。数秒で自動的に消え、複数同時表示は縦に積む。成功・エラーで色を分ける。
- **学び**: DOM 部品のモジュール化・`setTimeout`・要素の生成と削除・`common.css` への共通スタイル追加。
- **確認観点**: 在庫上限アラート・キャンセル失敗がトーストになる / 連続表示で重ならない / 消えた後に DOM に残らない。
